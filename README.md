# dots (server): ddm, the deployment manager

The one repo with CI and secrets. It declares which of your repos to build, with which reusable workflow, and where
each result is served under `cathe.dev` and `jpears.me`. Planned: ddm pulls this repo and rebuilds the server's NixOS
config from it, including updating itself.

**Status:** mostly design. See the docs site for what is real and what is planned.

## Docs

The documentation is a site, built from `mkdocs.yml` + `docs/` (planned host: `ddm.cathe.dev`):

```sh
nix develop -c mkdocs serve    # preview at http://127.0.0.1:8000
```

- `docs/usage/`: the site spec, adding a site, workflows, operations.
- `docs/design/`: decision record, architecture, open questions, roadmap.
- `DEVELOPMENT.md`: the design and development log up to 2026-10-18 (also rendered on the site); it continues in
  the private `devlog` repo, folder `webserver/`.

Pages generated by Claude carry `generated` front matter and get a yellow "generated by" header, drawn by ddm
(D56); a site or region can be marked in `sites.yaml` instead.

## Layout

- `sites.yaml`: the site spec. Check it with `nix develop -c bin/ddm check`.
- `ddm/`: the deployment manager (Go). It validates `sites.yaml` (`ddm check`, `ddm sites`) and builds sites locally
  (`ddm build`); publishing comes in M3. Run it from source with `nix develop -c bin/ddm …`.
- `scripts/`: helpers that workflows call (`generate_docs.py` for `ocaml-notebook`).
- `flake.nix`: the dev shell, plus the workflow environments `#mkdocs` and `#ocaml-docs`.
- `_example_yamls/`: the old per-repo GitHub Actions workflows that ddm's workflows replaced (reference only).
- `docs/`, `mkdocs.yml`, `overrides/`: the docs site.

The old setup (`webserver/`, `deploy.yaml`, the hand-written `Caddyfile`, the `deploy-dots` Action) was removed on
2026-10-16. It is still in git history, and still running on the droplet until that is reinstalled.
