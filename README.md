# dots (server): ddm, the deployment manager

The one repo with CI and secrets. It declares which of your repos to build, with which reusable workflow, and where
each result is served under `cathe.dev` and `jpears.me`. Planned: ddm pulls this repo and rebuilds the server's NixOS
config from it, including updating itself.

**Status:** mostly design. See the docs site for what is real and what is planned.

## Docs

The documentation is a site, built from `mkdocs.yml` + `docs/` (planned host: `ddm.cathe.dev`):

```sh
nix develop -c mkdocs serve    # preview at http://127.0.0.1:8000
```

- `docs/usage/`: the site spec, adding a site, workflows, operations.
- `docs/design/`: decision record, architecture, open questions, roadmap.
- `DEVELOPMENT.md`: the design and development log (also rendered on the site).

Pages generated by Claude carry `generated` front matter and render with a yellow "generated by" treatment.

## Layout today

- `Caddyfile`: live, hand-maintained Caddy config.
- `webserver/`: Go code (`webserver deploy`); sync and publish work, the build methods are stubs.
- `deploy.yaml`: the v1 spec read by `webserver/`; replaced by `sites.yaml` in roadmap M1.
- `_example_yamls/`: the per-repo GitHub Actions workflows that ddm replaces.
- `.github/workflows/deploy-dots.yml`: on push to `main`, pulls this repo on the droplet.
