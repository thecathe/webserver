# ddm: the deployment manager

!!! warning "Status: design"
    Most of what these pages describe is **designed but not built**. The old droplet still runs the previous hand-made
    setup, which will be wiped. `ddm/` validates the
    [site spec](usage/spec.md) and builds any site locally ([workflows](usage/workflows.md)), but doesn't publish yet. Each page says which parts are real.

## What it is for

One repo (this one) is the **only** place with GitHub secrets or CI. Everything else is declared in a spec:

- **Sites**: which of your repos to pull, which reusable **workflow** builds each one (forester, odoc, mkdocs, an
  OCaml "notebook" built from `.ml` files, …), and which **host and path** each output is mounted at.
- **The server itself**: ddm pulls this repo and rebuilds the droplet's NixOS configuration from it, including
  updating ddm itself.

Adding a new project means adding a spec entry, with no per-repo Actions, keys or secrets. That also makes it cheap
to stand up **project-specific sites** that a team can use, whether hosting material directly or redirecting to it.
